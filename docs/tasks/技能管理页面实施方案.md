## 二、技术方案

### 路由方案

采用与 cron 页面一致的 **hash 路由** 方式，在 `chat-standalone.ts` 中增加 `#skills` 路由判断：

```typescript
// 访问路径
/chat/standalone?session=agent:main:dashboard:xxx#skills
```

### 数据模型

扩展现有 `SkillDropdownEntry`，新增 `SkillCardEntry`：

```typescript
interface SkillCardEntry {
  skillKey: string;
  name: string;
  description: string;
  enabled: boolean;
  emoji?: string;
  // 扩展字段（需要后端 API 支持或前端模拟）
  iconChar?: string;       // 图标字符（如 "财"）
  iconColor?: string;      // 背景色（如 "#d19d4e"）
  tags?: string[];         // 标签列表
  status?: "idle" | "updating" | "update_available";
  avatarUrl?: string;      // 图片类型头像 URL（如 Nano Banana）
}
```

### API 调用

复用现有 `skills.status` 方法，并扩展返回字段：

```typescript
// 现有 API（state.ts loadSkillsList）
await client.request("skills.status", {})
// 返回：
{
  skills: Array<{
    disabled: boolean;
    name: string;
    skillKey: string;
    emoji?: string;
    description?: string;
    // 需扩展：
    iconChar?: string;
    iconColor?: string;
    tags?: string[];
    status?: string;
    avatarUrl?: string;
  }>;
}
```

> **注意**：如果后端 API 暂不支持扩展字段，前端需提供 fallback：
> - `iconChar` → 取 `name` 首字
> - `iconColor` → 按 skillKey hash 分配预设颜色
> - `tags` → 空数组
> - `status` → "idle"

## 七、注意事项

1. **API 兼容性**：如果后端 `skills.status` 不返回 tags/iconColor 等字段，前端需提供 fallback 逻辑
2. **路由一致性**：与 cron 页面保持相同的 hash 路由模式
3. **CSS 隔离**：技能页面样式使用 `.skills-` 前缀，避免与现有样式冲突
4. **响应式**：grid 布局使用 `auto-fill` + `minmax(329px, 1fr)` 自适应列数
5. **性能**：技能列表可能较长，搜索使用前端过滤（数据量小），不请求后端
